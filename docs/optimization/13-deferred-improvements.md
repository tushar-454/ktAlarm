# 13 — Deferred improvements and prerequisites

Phase 2 preserves the alarm engine and stops before production qualification. The following changes were investigated and deliberately left unapplied.

| Batch / finding | Reason for deferral | Benefit / evidence required next |
|---|---|---|
| 2 / S2: replace release signing | Existing installed/distributed identity is unknown; EAS artifact access was denied. A different certificate can break updates and cause uninstall/data loss. | Obtain distributed, installed and EAS certificate fingerprints; agree a compatible signing strategy and test update-over-install. No credentials should enter Git or logs. |
| 3 / Z3: Android-only `@expo/ui` exclusion | Direct app imports are confined to `time-picker.ios.tsx`, but installed Expo Router **does** load `@expo/ui/jetpack-compose` and modifiers through `build/optional-libraries/expo-ui.js`. Android stack toolbar components call that helper. App headers are hidden and no `Stack.Toolbar` is configured, but the transitive initialization path and screen/modal behavior have not been device-tested without the native module. | SDK 58 supports platform-specific autolinking exclusion. In an isolated future experiment use `expo.autolinking.android.exclude: ["@expo/ui"]`, retain iOS and `kt-alarm`, compare discovery/registration, release artifacts, all screens/time picker/modals and startup logcat. Compose/font savings remain unmeasured. |
| 4A / Z5: GIF decoder | No bundled app GIF or direct RN `Image` use was found in `src/`; image previews use `expo-image`, custom imports become JPEG. This is preliminary dependency evidence, not a format regression test across libraries/devices. | Isolate `expo.gif.enabled=false`, build an equivalent release, inspect removed libraries and test custom backgrounds, previews and screens. No measured saving exists. |
| 4B / Z5: WebP decoder | App launcher resources include WebP (system-decoded, distinct from Fresco). No direct app RN `Image` use was found, but transitive callers and format compatibility were not exercised. | Independently test `expo.webp.enabled=false` after GIF evaluation, inspect dependency/package changes and images. Preserve platform WebP icons. No measured saving exists. |
| 4C / Z6: resource shrinking | R8 already enabled; resource shrinking is off. AGP 9.2.1 supports the existing `shrinkResources` DSL, but resource stripping can affect alarm UI, raw sounds, Expo registration and ML Kit. Physical tests unavailable. | One-flag experiment via the existing `android.enableShrinkResourcesInReleaseBuilds` property; preserve every keep rule; inspect R8/resource diagnostics and run the full release matrix. Benefit unknown. |
| 5 / Z4: Reanimated / Worklets removal | `npm ls` shows Router → drawer-layout → Reanimated → Worklets; Router, `@expo/ui` and Expo Modules Core also have peer relationships. Babel preset automatically loads the installed Worklets plugin. Absence of app imports is insufficient proof of safe removal. | Trace actual production Metro/native usage, initialization and animation paths; test all UI/navigation and a clean supported install before considering removal. No dependency changed. |
| 6 / Z7: audio transcoding | Nine unique WAVs are referenced by `PresetMedia`; no exact duplicate unused asset was found. Changing bytes/format would require audio reliability testing and is prohibited here. | Potential compressed savings remain estimates from Phase 1. Require API 24+ playback, timing/duration, loop boundary, volume/fade, sleep timer and every preset alarm tests. Keep paths, identifiers and mappings stable. |
| 7 / S9: strip logs | Five info calls provide delivery/recovery diagnostics; no sensitive payload was found in those calls. Cosmetic reduction does not justify lost observability. | A demonstrated exposure plus a narrow safe replacement; preserve operational errors/warnings. |
| S1 / S4 / S5 | Explicitly protected receiver, mission authorization/process recovery and persistence semantics. | Separate compatibility plan with action/reboot matrix, process-death tests, malformed JSON/downgrade tests and physical update/data tests. |
| S3: backup rules | No backup/migration compatibility assessment. | Device-protected data scope, restore behavior and product policy, including Android-version/OEM differences. |
| ML Kit unbundling; other native removals | Offline first-launch pose/barcode functionality and transitive native requirements must remain supported. | Dependency proof and full offline camera/pose matrix; do not trade compatibility for size. |
| Startup initializers / AlarmStore caching | No measured severe bottleneck; touches critical initialization or persistence. | Release cold-start traces, realistic alarm counts, latency/battery/memory evidence. No performance benchmark or gain claimed. |
| Legacy native-library compression | APK-file versus installed-size/startup tradeoff; no measured net product benefit. | Controlled same-ABI download/install/startup comparison. Existing packaging retained. |
| npm advisory GHSA-g3hv-75wg-m249 | Approved scan reports one moderate `minimatch` advisory propagated through fingerprint/Expo. Tool-suggested Expo 52 change violates pinned dependencies; actual app exploitability is unproven. | Separate supported dependency-remediation review, assess build-tool versus mobile-runtime reachability and Expo-compatible patched resolution, then rerun advisory/static/release checks. |

The Phase 1 size estimates are hypotheses, not accepted savings. No audio, animation, image-format, backup, signing or alarm behavior change was retained. Future work should start from reports 09–12 and the unchanged regression plan 08; it must not assume compilation substitutes for physical testing.
